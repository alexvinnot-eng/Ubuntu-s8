# v0.2.1 TWRP unzip compatibility fix

The first SM-G955F installation attempt with v0.2.0 stopped safely before any
partition was written. The recovery `unzip -l` implementation could not report
the 3,984,588,800-byte `ubuntu.img` member as a positive shell integer and the
installer printed:

```
ERROR: ubuntu.img is missing or has an invalid size; nothing was flashed.
```

v0.2.1 removes the multi-gigabyte ZIP member. The build tool stores the exact
same ext4 image as numbered members of at most 256 MiB. The updater reads a
small size manifest for its free-space check, streams every member into
`/data/ubuntu.img.new`, verifies the SHA-256 of the completed image, atomically
renames it to `/data/ubuntu.img`, and only then writes BOOT.

Validated hashes:

- `boot.img`: `7808c46e992c4bc605b259033d2a54ea51e74f32538fc520c9e7aa4d83833cc9`
- reconstructed `ubuntu.img`: `b343f33cf9423fa2eaba5742546a1b7c6dea77d57def1090378b7ea0a54f651c`
- v0.2.1 TWRP ZIP: `0cac2154a3c756e79efe8e6ca9057b32ae9f2275876661168afe5329a883e29a`

`unzip -t` passes for every archive member, and streaming all fifteen rootfs
members reproduces the original `ubuntu.img` hash exactly. The archive does not
require ZIP64 and contains no individual member larger than 256 MiB.
