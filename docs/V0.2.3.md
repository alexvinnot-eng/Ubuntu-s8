# v0.2.3 console handoff fix

Hardware logs from the SM-G955F v0.2.2 test show that userdata, `ubuntu.img`
and the embedded Android API 30 image all mount successfully.  The handoff to
the Ubuntu rootfs stops when klibc `run-init` attempts to open `/dev/console`:

```text
run-init: opening console: No such device
Target filesystem doesn't have requested /sbin/init.
```

The second line is the generic fallback after `run-init` fails; the preceding
console error is the actual blocker.  All four embedded dream2lte DTBs carry
Samsung's `console=ram` boot argument, but this kernel has no `ram` console.

v0.2.3 changes exactly those four length-neutral DTB strings to `console=tty`.
The kernel console parser resolves `tty` with no explicit number to index 0,
equivalent to `tty0`.  Kernel, initramfs, image size and section offsets remain
unchanged.  The installer writes only BOOT and requires the existing
`/data/ubuntu.img` from v0.2.2.
