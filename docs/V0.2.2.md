# v0.2.2 TWRP userdata free-space parsing fix

The SM-G955F v0.2.1 installation stopped safely before writing rootfs or BOOT
despite TWRP reporting 49.6 GiB free on `/data`. On this recovery build, the
long userdata block-device name can occupy a separate display row in `df`
output. Reading only line two therefore produced an empty free-space value.

v0.2.2 reads the final `df` row and selects the available-space field relative
to the end of that row. It also explicitly validates that the result is a
non-empty integer before comparing it with the required rootfs size.

No rootfs, kernel, device configuration or partition-writing behavior changed
from v0.2.1. Rootfs is still verified before the atomic rename and BOOT is still
written only after successful rootfs verification.
